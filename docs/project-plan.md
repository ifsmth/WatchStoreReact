# План проєкту: Магазин наручних годинників

## 1. Тема та опис предметної області

**Тема:** Вебзастосунок для магазину наручних годинників.
**Проблема:** Необхідність зручної платформи для клієнтів, де вони можуть переглядати каталог годинників, фільтрувати їх за характеристиками та оформлювати замовлення, а також наявність зручної панелі керування для адміністраторів магазину.

## 2. Користувачі системи

У системі передбачено три основні ролі користувачів:

- **Відвідувач (Гість):** Може ознайомитися з асортиментом, переглядати каталог, використовувати фільтри (бренд, механізм, ціна) та переглядати сторінки товарів.
- **Покупець (Зареєстрований):** Має можливість швидко купити товар, оформлювати замовлення з кошика та мати доступ до історії покупок і статусів замовлень в особистому кабінеті.
- **Адміністратор:** Керує наповненням вітрини (додавання/редагування товарів) та обробляє запити клієнтів (зміна статусів замовлень).

## 3. Основні сценарії (Use Cases)

- **Пошук та перегляд годинників:** Відвідувач переходить до каталогу, використовує бічні фільтри (бренд, тип механізму, ціна) та переглядає детальні характеристики годинника на його сторінці.
- **Оформлення замовлення:** Авторизований покупець переходить до кошика, перевіряє перелік товарів та суму, після чого підтверджує покупку. Якщо користувач не залогінений, система перенаправляє його на сторінку авторизації.
- **Керування товарами (Адмін):** Адміністратор через Дашборд додає новий годинник, заповнюючи форму характеристик (бренд, ціна, залишок) та завантажуючи фотографії. Товар одразу з'являється у публічному каталозі.
- **Зміна статусу замовлення (Адмін):** Адміністратор переглядає нові замовлення, перевіряє дані клієнта та змінює статус (наприклад, на "В обробці" або "Відправлено").
- **Реєстрація та Авторизація:** Відвідувач заповнює форму реєстрації або логіну. Після успішної валідації система авторизує його та надає доступ до профілю.

## 4. Структура застосунку (Сторінки)

### Клієнтська частина

- **`/` (Головна):** Інформація про компанію, бренди та декілька карток популярних товарів.
- **`/products` (Каталог):** Відображення всіх товарів із пагінацією та бічним меню фільтрів (FilterSidebar).
- **`/products/:id` (Сторінка продукту):** Детальна інформація про годинник, вибір кількості та кнопка "Додати до кошика".
- **`/cart` (Кошик / Оформлення):** Перелік обраних товарів та оформлення замовлення.
- **`/login` та `/register`:** Сторінки авторизації та створення нового акаунту.
- **`/account`:** Особистий кабінет покупця з відображенням даних та історією замовлень.
- **`/account/edit` та `/account/edit/password`:** Сторінки зміни особистих даних або пароля.

### Адміністративна частина

- **`/admin/login`:** Сторінка входу для адміністратора.
- **`/admin` (Дашборд):** Загальна статистика магазину (товари, клієнти, замовлення).
- **`/admin/products` та `/admin/brands`:** Керування каталогом товарів та переліком брендів (створення, редагування, видалення).
- **`/admin/orders` та `/admin/orders/:id`:** Перелік усіх замовлень та детальне керування конкретним замовленням (редагування).
- **`/admin/users`:** Перегляд зареєстрованих клієнтів.

## 5. Основні сутності даних (Модель)

Система спирається на такі сутності бази даних:

- `brands` (Бренди годинників)
- `products` та `product_images` (Товари та їхні фотографії)
- `users` та `admins` (Користувачі та адміністратори)
- `orders` та `order_items` (Замовлення та їхні складові)

## 6. Поточний стан

- **Лабораторна 1.1 (Виконано):** Налаштовано середовище (Vite, ESLint), налаштовано Docker контейнеризацію. Створено цей план проєкту. Створено початковий інтерфейс каталогу з локальними даними.
- **Лабораторна 1.2 (Виконано):** Розроблено компонентну архітектуру (виділено шапку, навігацію, картки товарів, статус наявності через `StockBadge`, спільні UI-компоненти з використанням `children`). Створено статичні макети головної сторінки (`HomePage`), деталей товару (`ProductDetailsPage`) та форми оформлення замовлення (`CartPage`).
- **Лабораторна 2.1 (Виконано):** Впроваджено локальний стан (`useState`) та обробку подій. Створено керовану форму чернетки замовлення. Реалізовано фільтрацію каталогу через керовані компоненти із винесенням логіки у власний хук `useProductFilters`. Додано побічний ефект (`useEffect`) для синхронізації заголовка сторінки (`document.title`). Впроваджено `Context API` (`ProductSelectionProvider`) та компоненти-контейнери (`CatalogContainer`, `OrderContainer`) для управління глобальним станом.
- **Лабораторна 2.2 (Виконано):** Налаштовано повноцінну клієнтську маршрутизацію за допомогою `React Router`. Реалізовано переходи між сторінками каталогу, деталей товару та оформлення/редагування замовлень. Додано вкладені маршрути та параметризовані URL-адреси (`/products/:id`, `/orders/:orderId/edit`). Впроваджено збереження стану фільтрів у параметрах URL (`useSearchParams`). Створено сторінку обробки помилок навігації (404 Not Found) та проведено комплексний редизайн інтерфейсу застосунку.
- **Заплановано (Лабораторна 3.1):** Створення складних керованих форм, впровадження надійної валідації введених користувачем даних (форми замовлення, реєстрації), опрацювання подій відправлення даних та підготовка архітектури до роботи з асинхронними запитами на сервер.
