# Архітектура компонентів (Лабораторна робота 1.2 та 2.1)

Цей документ описує компонентну ієрархію, відповідальності, контракти властивостей (props) та керування станом вебзастосунку «Магазин годинників».

## 1. Ієрархія компонентів

Дерево відображення компонентів побудоване за принципом композиції та розділення логіки через контейнери:

- **`App`** (Кореневий компонент)
  - **`AppLayout`** (Спільна оболонка)
    - `SiteHeader` (Шапка сайту)
      - `MainNav` (Навігаційне меню за посиланнями)
    - `<main>` (Основний контейнер вмісту)
      - **`ProductSelectionProvider`** (Контекст вибору товару)
        - **`CatalogContainer`** (Підключення каталогу до контексту)
          - **`HomePage`** (Сторінка каталогу)
            - `Section` (Секція "Про магазин")
            - `Section` (Секція "Каталог товарів")
              - `ProductFilters` (Керовані фільтри)
              - `ProductList` (Список товарів)
                - `ProductCard` (Картка окремого годинника)
                  - `StockBadge` (Статус наявності товару)
                  - `AppButton` (Кнопка взаємодії)
                - `EmptyState` (Виводиться, якщо нічого не знайдено)
        - **`OrderContainer`** (Підключення замовлення до контексту)
          - **`OrderPage`** (Сторінка оформлення замовлення / Деталі)
            - `Section` (Секція деталей та форми)
              - `OrderSummary` (Підсумок замовлення)
              - `OrderForm` (Керована форма)
                - `FormField` (Компонування полів вводу з підписами)
                - `AppButton` (Кнопки дій: очистити / надіслати)
    - `<footer>` (Підвал застосунку)

## 2. Контракти ключових компонентів (Props)

| Компонент              | Вхідні властивості (Props)                           | Домовленість та відповідальність                                            |
| :--------------------- | :--------------------------------------------------- | :-------------------------------------------------------------------------- |
| **`AppLayout`**        | `title`, `links`, `children`                         | Створює спільну оболонку (шапку, навігацію, головний контейнер та футер).   |
| **`Section`**          | `id`, `title`, `children`                            | Формує семантичну секцію з унікальним `id` та заголовком `<h2>`.            |
| **`MainNav`**          | `links`                                              | Масив об'єктів з полями `href` та `label` для побудови навігації.           |
| **`CatalogContainer`** | _(немає)_                                            | Обгортка, що дістає стан вибору з Context API та передає його в `HomePage`. |
| **`OrderContainer`**   | _(немає)_                                            | Обгортка, що передає обраний об'єкт годинника з контексту в `OrderPage`.    |
| **`ProductFilters`**   | `query`, `availableOnly`, `onQueryChange`, ...       | Керовані фільтри. Викликає колбеки при зміні тексту або прапорця.           |
| **`ProductList`**      | `items`, `selectedId`, `onSelect`                    | Масив товарів. За порожнього масиву виводить `EmptyState`.                  |
| **`ProductCard`**      | `item`, `isSelected`, `onSelect`                     | Об'єкт товару з бази даних. Містить кнопку для вибору предмета.             |
| **`StockBadge`**       | `stock`                                              | Числове значення залишку. Формує текстовий статус і колір наявності.        |
| **`OrderForm`**        | `draft`, `onChange`, `onSubmit`                      | Керована форма замовлення, яка отримує значення з об'єкта чернетки.         |
| **`FormField`**        | `id`, `label`, `hint`, `children`                    | Обгортка поля форми. Забезпечує зв'язок підпису (`label`) з полем вводу.    |
| **`AppButton`**        | `children`, `type`, `variant`, `disabled`, `onClick` | Універсальна кнопка. Підтримує варіанти оформлення та ARIA-атрибути.        |

## 3. Карта стану (State Map)

| Стан (State)                     | Власник стану (Owner)      | Споживачі (Consumers)                | Механізм передачі / Керування                                                                  |
| :------------------------------- | :------------------------- | :----------------------------------- | :--------------------------------------------------------------------------------------------- |
| **`selectedId`**                 | `ProductSelectionProvider` | `CatalogContainer`, `OrderContainer` | Context API (`useProductSelection`) / Функції `handleSelect`, `handleClearSelection`           |
| **`query`**, **`availableOnly`** | `useProductFilters` (Hook) | `HomePage`, `ProductFilters`         | Повертається з кастомного хука / Сетери `setQuery`, `setAvailableOnly`, `resetFilters`         |
| **`isExpanded`**                 | `ProductCard` (Local)      | `ProductCard`                        | Локальний `useState` всередині картки для згортання/розгортання детального опису               |
| **`draft`**                      | `OrderPage` (Local)        | `OrderForm`, `OrderSummary`          | Локальний `useState` чернетки замовлення (`name`, `comment`). Скидається через `key={item.id}` |

## 4. Побічні ефекти (Side Effects)

- **Зміна заголовка вкладки (`document.title`):** Реалізовано через `useEffect` у компоненті `OrderPage`. При виборі годинника заголовок змінюється на `"Замовлення: <Назва_годинника>"`, а при розмонтуванні (очищенні) повертається до початкового значення `"Магазин годинників"`.

---

## 5. Обґрунтування головних рішень

1. **Впровадження Context API та контейнерів:** Стан обраного товару винесено у `ProductSelectionProvider`. Це дозволило розвантажити кореневий `App` та уникнути "прокидання" пропсів (prop drilling). Компоненти `CatalogContainer` та `OrderContainer` відповідають виключно за зв'язок сторінок із контекстом.
2. **Винесення `StockBadge` в окремий компонент:** Логіка визначення наявності товару за кількістю (`stock > 0`) ізольована в одному місці, що усуває дублювання коду між каталогом та сторінкою деталей.
3. **Використання композиції (`children`):** Такі компоненти, як `Section`, `AppLayout` та `FormField`, приймають контент через `children`. Це робить їх універсальними та дозволяє вільно змінювати внутрішню структуру без переписування каркаса.
4. **Власний хук `useProductFilters`:** Логіку роботи пошуку та фільтрації за наявністю винесено в окремий кастомний хук. Це зробило компонент `HomePage` чистішим: він відповідає лише за компонування UI, а не за математику фільтрації.
