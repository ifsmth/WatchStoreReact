# Архітектура компонентів (Лабораторна робота 1.2, 2.1, 2.2 та 3.1)

Цей документ описує компонентну ієрархію, відповідальності, контракти властивостей (props) та керування станом вебзастосунку «Магазин годинників».

## 1. Ієрархія компонентів

Дерево відображення компонентів побудоване за принципом композиції, а навігація реалізована через клієнтський маршрутизатор (React Router):

- **`App`** (Кореневий компонент, зберігає тестові масиви даних та налаштовує роутер)
  - **`AppLayout`** (Спільна оболонка для всіх сторінок)
    - `SiteHeader` (Шапка сайту)
      - `MainNav` (Навігаційне меню з використанням `NavLink`)
    - `<main>` (Основний контейнер вмісту, де рендериться `<Outlet>`)
      - **`ProductSelectionProvider`** (Контекст для збереження останнього обраного товару)
      - **`OrdersProvider`** (Провайдер колекції замовлень із підтримкою CRUD)
        - **`HomePage`** (Шлях: `/products` — Каталог)
          - `ProductFilters` (Керовані фільтри через URL)
          - `ProductList` (Список товарів)
            - `ProductCard` (Картка годинника із посиланням `Link` на деталі)
        - **`ProductDetailsPage`** (Шлях: `/products/:productId` — Деталі)
          - `StockBadge` (Статус наявності)
        - **`OrdersLayout`** (Шлях: `/orders` — Вкладена оболонка для розділу замовлень)
          - `OrderNotice` (Вивід повідомлень про успішні операції CRUD)
          - **`OrdersPage`** (Шлях: `/orders` — Таблиця списку замовлень)
            - `OrderFilters` (Пошук та сортування поточних замовлень)
            - `OrderTable` (Подання відібраних замовлень)
          - **`OrderCreatePage`** (Шлях: `/orders/new` — Нове замовлення)
            - **`CartPage`** (Перевикористовуваний редактор замовлення)
          - **`OrderDetailsPage`** (Шлях: `/orders/:orderId` — Перегляд збереженого запису)
          - **`OrderEditPage`** (Шлях: `/orders/:orderId/edit` — Редагування існуючого)
            - **`CartPage`** (Перевикористовуваний редактор замовлення)
              - `OrderSummary` (Підсумок)
              - `OrderForm` (Керована форма)
                - `FormField` (Компонування полів вводу з підписами та помилками)
    - `<footer>` (Підвал застосунку)

## 2. Контракти ключових компонентів (Props)

| Компонент                | Вхідні властивості (Props)                     | Домовленість та відповідальність                                                                        |
| :----------------------- | :--------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| **`AppLayout`**          | `title`, `links`, `children`                   | Створює спільну оболонку (шапку, навігацію, головний контейнер та футер).                               |
| **`OrdersLayout`**       | _(немає)_                                      | Вкладена оболонка для розділу замовлень. Містить власне міні-меню та `<Outlet>`.                        |
| **`ProductDetailsPage`** | `items`                                        | Отримує ID з URL (`useParams`), шукає товар та виводить його повні характеристики.                      |
| **`OrderDetailsPage`**   | `items`                                        | Виводить дані збереженого замовлення зі спільної колекції.                                              |
| **`OrderEditPage`**      | `items`                                        | Отримує ID замовлення з URL, знаходить його та пов'язаний товар, передає дані у `CartPage`.             |
| **`CartPage`**           | `title`, `item`, `initialDraft`, `onSave`...   | Універсальний редактор замовлення (використовується і для створення, і для редагування).                |
| **`OrderForm`**          | `draft`, `errors`, `onDraftChange`, `onSubmit` | Керована форма замовлення. Вимикає нативну валідацію (`noValidate`) для показу власних помилок.         |
| **`FormField`**          | `id`, `label`, `hint`, `error`, `children`     | Обгортка поля форми. Забезпечує зв'язок підпису (`label`), підказки та помилки (`error`) з полем вводу. |
| **`OrderFilters`**       | `query`, `sort`, `onQueryChange`...            | UI фільтрів замовлень. Викликає колбеки, які змінюють параметри URL.                                    |
| **`OrderTable`**         | `orders`, `items`, `onDelete`                  | Таблиця замовлень, яка отримує вже відфільтровані та відсортовані записи.                               |

## 3. Контракти операцій із замовленнями (CRUD)

Ці операції надаються контекстом `OrdersContext` і гарантують незмінне оновлення (immutable updates) стану колекції.

| Операція      | Вхід                 | Успіх                  | Відмова                           |
| :------------ | :------------------- | :--------------------- | :-------------------------------- |
| `createOrder` | Поля замовлення      | `{ ok: true, record }` | Помилки полів валідації           |
| `updateOrder` | Ідентифікатор і поля | `{ ok: true, record }` | Помилки полів або відсутній запис |
| `deleteOrder` | Ідентифікатор        | `{ ok: true }`         | Відсутній запис                   |
| Перегляд      | Ідентифікатор        | Знайдений запис        | Сторінка відсутнього маршруту     |

## 4. Сервісний шар та Асинхронний контракт (Доступ до даних)

Дані застосунку відокремлені від UI через єдиний сервісний контракт. Вибір джерела даних (`mock` або `api`) відбувається автоматично на основі змінної середовища `VITE_DATA_SOURCE`.

| Сервіс / Модуль       | Відповідальність                                                                                                                         |
| :-------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- |
| `orderContract.js`    | Перевірка даних на межі сервісу (валідація входів та перевірка структури отриманих записів).                                             |
| `mockOrderService.js` | Автономне джерело. Реалізує CRUD з імітацією мережевої затримки, відмов та збереженням у `localStorage`.                                 |
| `apiOrderService.js`  | REST API адаптер. Використовує `fetch`, обробляє HTTP-статуси (400, 404, 500 тощо) та читає JSON.                                        |
| `OrdersProvider.jsx`  | Зберігає поточний знімок даних для UI. Керує станами `loading`, `error`, `success`. Виконує послідовне оновлення без дублювання запитів. |

## 5. Карта стану (State Map)

| Стан (State)                        | Власник стану (Owner)              | Споживачі (Consumers)                        | Механізм передачі / Керування                                                                                           |
| :---------------------------------- | :--------------------------------- | :------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------- |
| **`orders`, `notice`**              | `OrdersProvider`                   | Сторінки замовлень, `OrderNotice`            | Спільна колекція даних у пам'яті. Змінюється через синхронні операції `createOrder`, `updateOrder`, `deleteOrder`.      |
| **`query`**, **`sort`**             | **URL Address** (`?q=...`)         | `useOrderFilters`, `OrderFilters`            | Стан зберігається в адресному рядку (`useSearchParams`). Дозволяє ділитися посиланнями на відфільтрований список.       |
| **`productId` (нове)**              | **URL Address** (`?productId=...`) | `OrderCreatePage`, `ProductSelectionContext` | Читається через `useSearchParams()`. Забезпечує збереження обраного товару навіть після перезавантаження сторінки (F5). |
| **`productId` (деталі), `orderId`** | **URL Address** (`/:id`)           | Сторінки деталей та редагування              | Читається через `useParams()`. Зв'язує сторінку з конкретним записом колекції.                                          |
| **`draft`**, **`errors`**           | `CartPage` (Local)                 | `OrderForm`, `OrderSummary`                  | Локальний `useState` чернетки. Помилки обчислюються на льоту чистою функцією `validateOrder`.                           |

## 6. Обґрунтування головних рішень

1. **Одна функція валідації:** Створено чисту функцію `validateOrder`, яка перевіряє правила та нормалізує значення (наприклад, перетворює `quantity` з рядка на число та прибирає пробіли у тексті). Вона повторно використовується і для створення, і для редагування записів.
2. **Незмінні операції над колекцією:** Методи оновлення (`setOrders`) використовують функціональну форму (updater) та прийоми незмінного оновлення (`filter`, `map`, поширення об'єктів), не мутуючи початковий масив стану.
3. **Локальна чернетка:** Введення тексту відбувається у локальний стан чернетки. Запис у спільній колекції оновлюється лише після проходження перевірки та підтвердження форми.
4. **Узгоджений список:** Пошук та сортування обчислюються "на льоту" зі спільної колекції без зміни самого джерела даних. Записи сортуються за числовими значеннями або рядками з урахуванням локалі (через `localeCompare`).
5. **Єдина процедура підтвердження:** Створено хук `useDeleteOrder`, який поєднує виклик контексту з вікном підтвердження (`window.confirm`), запобігаючи випадковому видаленню та зменшуючи дублювання коду.
