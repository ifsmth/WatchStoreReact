# Архітектура компонентів (Лабораторна робота 1.2, 2.1 та 2.2)

Цей документ описує компонентну ієрархію, відповідальності, контракти властивостей (props) та керування станом вебзастосунку «Магазин годинників».

## 1. Ієрархія компонентів

Дерево відображення компонентів побудоване за принципом композиції, а навігація реалізована через клієнтський маршрутизатор (React Router):

- **`App`** (Кореневий компонент, зберігає тестові масиви даних та налаштовує роутер)
  - **`AppLayout`** (Спільна оболонка для всіх сторінок)
    - `SiteHeader` (Шапка сайту)
      - `MainNav` (Навігаційне меню з використанням `NavLink`)
    - `<main>` (Основний контейнер вмісту, де рендериться `<Outlet>`)
      - **`ProductSelectionProvider`** (Контекст для збереження останнього обраного товару)
        - **`HomePage`** (Шлях: `/products` — Каталог)
          - `ProductFilters` (Керовані фільтри через URL)
          - `ProductList` (Список товарів)
            - `ProductCard` (Картка годинника із посиланням `Link` на деталі)
        - **`ProductDetailsPage`** (Шлях: `/products/:productId` — Деталі)
          - `StockBadge` (Статус наявності)
        - **`OrdersLayout`** (Шлях: `/orders` — Вкладена оболонка для розділу замовлень)
          - **`OrdersPage`** (Шлях: `/orders` — Таблиця списку замовлень)
          - **`OrderCreatePage`** (Шлях: `/orders/new` — Нове замовлення)
            - **`CartPage`** (Перевикористовуваний редактор замовлення)
          - **`OrderEditPage`** (Шлях: `/orders/:orderId/edit` — Редагування існуючого)
            - **`CartPage`** (Перевикористовуваний редактор замовлення)
              - `OrderSummary` (Підсумок)
              - `OrderForm` (Керована форма)
                - `FormField` (Компонування полів вводу з підписами)
    - `<footer>` (Підвал застосунку)

## 2. Контракти ключових компонентів (Props)

| Компонент                | Вхідні властивості (Props)                     | Домовленість та відповідальність                                                            |
| :----------------------- | :--------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **`AppLayout`**          | `title`, `links`, `children`                   | Створює спільну оболонку (шапку, навігацію, головний контейнер та футер).                   |
| **`OrdersLayout`**       | _(немає)_                                      | Вкладена оболонка для розділу замовлень. Містить власне міні-меню та `<Outlet>`.            |
| **`ProductDetailsPage`** | `items`                                        | Отримує ID з URL (`useParams`), шукає товар та виводить його повні характеристики.          |
| **`OrderEditPage`**      | `orders`, `items`                              | Отримує ID замовлення з URL, знаходить його та пов'язаний товар, передає дані у `CartPage`. |
| **`CartPage`**           | `title`, `item`, `initialDraft`, `onCancel`    | Універсальний редактор замовлення (використовується і для створення, і для редагування).    |
| **`ProductFilters`**     | `query`, `availableOnly`, `onQueryChange`, ... | UI фільтрів. Викликає колбеки, які змінюють параметри URL.                                  |
| **`ProductList`**        | `items`                                        | Масив товарів для виводу сітки. За порожнього масиву виводить `EmptyState`.                 |
| **`ProductCard`**        | `item`                                         | Об'єкт товару з бази даних. Містить посилання на сторінку деталей.                          |
| **`StockBadge`**         | `stock`                                        | Числове значення залишку. Формує текстовий статус і колір наявності.                        |
| **`OrderForm`**          | `draft`, `onDraftChange`, `onReset`            | Керована форма замовлення, яка отримує значення з об'єкта чернетки.                         |
| **`FormField`**          | `id`, `label`, `hint`, `children`              | Обгортка поля форми. Забезпечує зв'язок підпису (`label`) з полем вводу.                    |

## 3. Карта стану (State Map)

| Стан (State)                     | Власник стану (Owner)      | Споживачі (Consumers)                   | Механізм передачі / Керування                                                                                         |
| :------------------------------- | :------------------------- | :-------------------------------------- | :-------------------------------------------------------------------------------------------------------------------- |
| **`query`**, **`availableOnly`** | **URL Address** (`?q=...`) | `useProductFilters`, `ProductFilters`   | Стан зберігається в адресному рядку (`useSearchParams`). Це дозволяє ділитися посиланнями на відфільтрований каталог. |
| **`productId`**, **`orderId`**   | **URL Address** (`/:id`)   | Сторінки деталей та редагування         | Читається через `useParams()` або `useSearchParams()`. Зв'язує сторінку з конкретним записом бази даних.              |
| **`selectedId`**                 | `ProductSelectionProvider` | `OrderCreatePage`, `ProductDetailsPage` | Context API (`useProductSelection`). Використовується для "запам'ятовування" вибору між переходами.                   |
| **`draft`**                      | `CartPage` (Local)         | `OrderForm`, `OrderSummary`             | Локальний `useState` чернетки. Скидається при зміні товару/замовлення завдяки використанню атрибута `key`.            |

## 4. Побічні ефекти (Side Effects)

- **Синхронізація заголовка вкладки (`document.title`):** Реалізовано через `useEffect`. При переході на різні сторінки (наприклад, перегляд деталей або оформлення замовлення) заголовок браузера динамічно змінюється, що покращує користувацький досвід та доступність.

---

## 5. Обґрунтування головних рішень

1. **Впровадження React Router:** Відмова від ручного керування відображенням на користь декларативного маршрутизатора. Це забезпечило роботу стандартних функцій браузера (кнопки "Назад/Вперед") та можливість створення прямих посилань на товари.
2. **URL як джерело правди для фільтрів:** Стан пошуку та чекбоксу "в наявності" перенесено з локального `useState` у параметри URL (через `useSearchParams`). Це зробило стан фільтрації частиною історії браузера.
3. **Вкладена навігація (`OrdersLayout`):** Розділ замовлень винесено у власну підструктуру з окремим меню. Це демонструє здатність масштабувати застосунок без перевантаження головного меню.
4. **Універсальність `CartPage`:** Компонент редактора замовлення спроєктовано так, щоб він приймав `initialDraft` та `item` через props. Це дозволило перевикористати його як для сторінки створення (`OrderCreatePage`), так і для редагування (`OrderEditPage`), уникнувши дублювання коду.
5. **Захист від помилок (Early Return):** На сторінках деталей та редагування додано перевірки наявності записів. Якщо `item` не знайдено (наприклад, невірний ID в URL), компоненти коректно повертають заглушку `NotFoundPage` або `EmptyState`, запобігаючи падінню всього застосунку.
