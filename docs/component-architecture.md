# Архітектура компонентів та системи (Підготовка до курсової роботи)

Цей документ описує повну компонентну ієрархію, контексти керування станом, контракти властивостей (props), сервісний шар та бізнес-логіку вебзастосунку «ChronoClassic».

---

## 1. Ієрархія компонентів та маршрутизація

Дерево застосунку побудоване за принципом компонентної композиції. На верхньому рівні підключаються глобальні контексти даних, допоміжні утиліти (скрол до верху сторінки) та маршрутизатор `React Router`:

    │   │   │           └── ProductCard (картка товару)

## 2. Контракти ключових компонентів (Props)

| Компонент                  | Вхідні властивості (Props)                     | Відповідальність та поведінка                                                                                          |
| :------------------------- | :--------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- |
| **`AppLayout`**            | _(немає)_                                      | Клієнтський лейаут: містить `SiteHeader`, динамічну зону `<Outlet />` та `SiteFooter`.                                 |
| **`AdminLayout`**          | _(немає)_                                      | Адміністративний лейаут: панель меню, `AdminHeader`, робоча область `<Outlet />` та `AdminFooter`.                     |
| **`ProtectedRoute`**       | `children`                                     | Перевіряє наявність активної сесії користувача у `AuthContext`. Перенаправляє на `/login`, якщо користувач не увійшов. |
| **`ScrollToTop`**          | _(немає)_                                      | Слухає зміни в `useLocation().pathname` і виконує `window.scrollTo({ top: 0, left: 0, behavior: "instant" })`.         |
| **`ProductCard`**          | `product`, `onSelect`                          | Відображає картку годинника (фото, бренд, назву, ціну, бейдж наявності), надає посилання на сторінку деталей.          |
| **`ProductFilters`**       | `filters`, `brands`, `onFilterChange`          | Панель фільтрації каталогу (цінові межі, бренди, механізми, стать). Синхронізується з параметрами URL.                 |
| **`CartPage`**             | `title`, `initialDraft`, `onSave`              | Редактор/оформлювач замовлення: список позицій, поле коментаря, керована форма покупця та підсумок.                    |
| **`OrderForm`**            | `draft`, `errors`, `onDraftChange`, `onSubmit` | Керована форма замовлення без нативної валідації (`noValidate`) із відображенням детальних помилок полів.              |
| **`FormField`**            | `id`, `label`, `hint`, `error`, `children`     | Універсальна обгортка для полів вводу із доступністю (accessibility), мітками та повідомленнями про помилки.           |
| **`OrderTable`**           | `orders`, `items`, `onDelete`                  | Таблиця замовлень, що приймає відфільтровані та відсортовані записи.                                                   |
| **`AdminProductFormPage`** | _(визначається URL: `:id` або `create`)_       | Створення/редагування товару з валідацією полів, вибірковим механізмом, числовим водозахистом та прев'ю кількох фото.  |

## 3. Керування станом (Context Architecture)

У системі реалізовано модульну архітектуру стану через React Context API:

| Контекст                      | Збережений стан                            | Надані методи / дії                                                                                           |
| :---------------------------- | :----------------------------------------- | :------------------------------------------------------------------------------------------------------------ |
| **`AuthContext`**             | `user`, `token`, `role`, `isAuthenticated` | `login(credentials)`, `register(data)`, `logout()`, `updateProfile(data)`, `changePassword(passwords)`        |
| **`CatalogContext`**          | `products`, `brands`, `loading`, `error`   | `createProduct()`, `updateProduct()`, `deleteProduct()`, `createBrand()`, `deleteBrand()`, `refreshCatalog()` |
| **`CartContext`**             | `cartItems`, `totalCount`, `totalPrice`    | `addToCart(product, quantity)`, `removeFromCart(id)`, `updateQuantity(id, qty)`, `clearCart()`                |
| **`OrdersContext`**           | `orders`, `notice`, `loading`, `error`     | `createOrder(data)`, `updateOrder(id, data)`, `deleteOrder(id)`, `updateOrderStatus(id, status)`              |
| **`MessagesContext`**         | `messages`                                 | `addMessage(data)`, `markAsProcessed(id)`                                                                     |
| **`ProductSelectionContext`** | `selectedProductId`                        | `setSelectedProductId(id)` (синхронізація останнього переглянутого товару)                                    |

## 4. Сервісний шар та Асинхронний контракт

Доступ до даних повністю абстрагований від інтерфейсу компонентів. Вибір джерела даних регулюється змінною середовища `VITE_DATA_SOURCE` (`mock` або `api`).

```
UI Компоненти / Сторінки
         │
         ▼
Контексти (OrdersContext, CatalogContext, AuthContext, MessagesContext)
         │
         ▼
Фасадні сервіси (orderService, catalogService, authService, applicationService)
         │
    ┌────┴───────────────────────────┐
    ▼                                ▼
mockOrderService (localStorage)    apiOrderService / apiClient (REST API)
```

- **`orderContract.js`:** Вхідний контракт для валідації структури даних перед відправкою до сервісів.
- **`mockOrderService.js`:** Автономне сховище на базі `localStorage` з емуляцією асинхронних затримок мережі.
- **`apiOrderService.js` / `apiClient.js`:** Адаптери клієнтських запитів через `fetch`, що підтримують стандартизовану обробку HTTP-помилок, формат JSON та токени авторизації.
- **`mappers.js`:** Нормалізація структур даних між форматом бекенду (snake_case) та фронтенду (camelCase).

## 5. Чиста предметна логіка (Domain Functions)

Для полегшення тестування та запобігання дублюванню коду бізнес-правила винесено у чисті функції:

1. **`orderValidation.js`:**
   - Перевіряє коректність імені покупця (мінімум 2 символи, без заборонених символів).
   - Валідує телефон (український формат номерів) та електронну адресу.
   - Перевіряє кількість товару (ціле додатне число в межах залишку).
   - Нормалізує рядки (обрізка зайвих пробілів).
2. **`selectOrders.js`:**
   - Фільтрація списку замовлень за пошуковим запитом (ім'я, телефон, адреса, назва товару).
   - Сортування колекції за датою створення, сумою або статусом із урахуванням локалі (`localeCompare`).

## 6. Стратегія тестування (31 тест)

Застосунок покритий тестами за допомогою `Vitest` та `@testing-library/react`:

1. **Модульні тести доменної логіки (`orderValidation.test.js` — 7 тестів):**
   - Перевірка обов'язкових полів, мінімальної довжини, коректності email/телефону, нормалізації даних.
2. **Модульні тести вибірки (`selectOrders.test.js` — 3 тести):**
   - Пошук за запитом, сортування за зростанням/спаданням, робота з порожніми результатами.
3. **Тести сервісного контракту (`apiOrderService.test.js` — 4 тести):**
   - Успішні запити створення/читання, обробка помилок сервера (400, 404, 500), правильність формування тіла запитів.
4. **Компонентні тести форми (`CartPage.test.jsx` — 3 тести):**
   - Рендеринг форми замовлення, реакція на помилки валідації, збереження чернетки замовлення.
5. **Інтеграційні тести застосунку (`App.integration.test.jsx` — 14 тестів):**
   - Повноцінна навігація клієнтськими маршрутами, додавання товару з каталогу в замовлення, оформлення покупки, перегляд деталей та редагування замовлень.
