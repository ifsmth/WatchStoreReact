# Архітектура компонентів (Лабораторна робота 1.2)

Цей документ описує компонентну ієрархію, відповідальності та контракти властивостей (props) вебзастосунку «Магазин годинників».

## 1. Ієрархія компонентів

Дерево відображення компонентів побудоване за принципом композиції:

- **`App`** (Кореневий компонент)
  - **`App`** (Спільна оболонка)
    - `SiteHeader` (Шапка сайту)
      - `MainNav` (Навігаційне меню за посиланнями)
    - `<main>` (Основний контейнер вмісту)
      - **`HomePage`** (Сторінка каталогу)
        - `Section` (Секція "Про магазин")
        - `Section` (Секція "Каталог товарів")
          - `ProductList` (Список товарів)
            - `ProductCard` (Картка окремого годинника)
              - `StockBadge` (Статус наявності товару)
            - `EmptyState` (Виводиться, якщо масив товарів порожній)
      - **`ProductDetailsPage`** (Сторінка деталей товару)
        - `Section` (Секція з детальними характеристиками)
          - `StockBadge` (Статус наявності)
          - `AppButton` (Кнопка "Додати до кошика")
          - `EmptyState` (Виводиться, якщо товар не вибрано)
      - **`CartPage`** (Макет оформлення замовлення)
        - `Section` (Секція кошика та форми)
          - `FormField` (Компонування полів вводу з підписами)
          - `AppButton` (Кнопки дій: очистити / надіслати)
    - `<footer>` (Підвал застосунку)

## 2. Контракти ключових компонентів (Props)

| Компонент                | Вхідні властивості (Props)                | Домовленість та відповідальність                                                               |
| :----------------------- | :---------------------------------------- | :--------------------------------------------------------------------------------------------- |
| **`AppLayout`**          | `title`, `links`, `children`              | Створює спільну оболонку (шапку, навігацію, головний контейнер та футер)[cite: 2].             |
| **`Section`**            | `id`, `title`, `children`                 | Формує семантичну секцію з унікальним `id` та заголовком `<h2>`[cite: 2].                      |
| **`MainNav`**            | `links`                                   | Масив об'єктів з полями `href` та `label` для побудови навігації[cite: 2].                     |
| **`ProductList`**        | `items`                                   | Масив товарів. Допускає порожній масив (`[]`), у такому разі відображає `EmptyState`[cite: 2]. |
| **`ProductCard`**        | `item`                                    | Коректний об'єкт товару з бази даних (містить `title`, `price`, характеристики тощо)[cite: 2]. |
| **`StockBadge`**         | `stock`                                   | Числове значення залишку. Формує текстовий статус і колір наявності[cite: 2].                  |
| **`ProductDetailsPage`** | `item`                                    | Об'єкт товару або `undefined` (передбачає випадок відсутності вибраного предмета)[cite: 2].    |
| **`FormField`**          | `id`, `label`, `hint`, `children`         | Обгортка поля форми. Забезпечує зв'язок підпису (`label`) з дочірнім елементом вводу[cite: 2]. |
| **`AppButton`**          | `children`, `type`, `variant`, `disabled` | Універсальна кнопка. Підтримує варіанти оформлення `primary` / `secondary`[cite: 2].           |

## 3. Обґрунтування головних рішень

1. **Винесення `StockBadge` в окремий компонент:** Правило визначення наявності товару за кількістю (`stock > 0`) використовується як у картках каталогу, так і на сторінці деталей товару. Винесення його в окремий компонент усуває дублювання логіки[cite: 2].
2. **Використання композиції (`children`):** Такі компоненти, як `Section`, `AppLayout` та `FormField`, приймають контент через `children`. Це робить їх універсальними та дозволяє змінювати внутрішню структуру сторінок чи форм без переписування каркаса[cite: 2].
3. **Статичний макет форм:** Усі форми реалізовані з перехопленням події подання (`onSubmit={(e) => e.preventDefault()}`), оскільки управління станом та валідація будуть додані в наступних лабораторних роботах (Л 2.1 та Л 3.1)[cite: 2].
